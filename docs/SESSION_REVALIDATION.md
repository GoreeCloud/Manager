# Manager — private session revalidation (development candidate)

**Scope:** Private Cloudflare Access-protected Manager web UI. **Status:** Mainline-based development candidate; locally unit-tested and exercised in a simulated Chromium browser. Cloudflare Access end-to-end logout and deployed-runtime acceptance remain unverified.

On returning to a visible Manager tab, restoring its page from browser history, or focusing its window, the browser requests `GET /api/session` with same-origin credentials and no-store caching. The endpoint inherits the mandatory root `functions/_middleware.js` Cloudflare Access JWT middleware, protecting both static assets and API endpoints, refuses direct calls without a verified viewer, and returns only `{"authenticated":true}`. It does not query GitHub, Cloudflare Pages, or OpenAI reporting endpoints; no identity attributes or credentials are returned.

Only a successful JSON response with `authenticated: true` preserves the existing dashboard. A 200 HTML login/fallback page, invalid JSON or an ambiguous response is rejected. The browser hides the existing private dashboard immediately when revalidation begins. A successful session check restores the previous verified snapshot, while a failed or unavailable check discards the data and asks the user to sign in and explicitly refresh. A monotonically increasing request revision prevents an older overview response from repopulating cleared private DOM. A newer overview refresh also takes ownership over an older tab-return check. No periodic provider polling, stored session token, or paid API retry is introduced.

**Limits:** This is UI data-minimization defense-in-depth, not server-side token/cookie revocation. Cloudflare Access must protect every production and preview domain, and every private API request remains independently authenticated. An already-visible idle tab is not automatically cleared on remote logout until an Access request or tab-return check occurs. Browsers without focus/visibility events require manual Refresh. Clearing on temporary network failure is deliberately fail-closed.

**Verification:** Unit tests cover endpoint authorization, sanitization, GET-only semantics, no-store, and source-level browser invalidation contracts. Node syntax and unit tests passed (57/57 on the development branch). A Chromium mobile-width smoke test with simulated requests verified data is hidden while revalidation is pending, retained on a positive response, and cleared after a denial, without page errors or horizontal overflow. Before production deployment, validate two-tab real Cloudflare Access logout/expiration, token/session revocation semantics, reload/back-forward and offline/reconnect behavior on every origin; verify data remains unavailable to non-owners. No production tokens or user data are required for synthetic tests.
